# Model 2/14: S5

Code: `src/ssm_lab/layers/s5.py` · Notebook: `notebooks/02_s5.ipynb` · Tests: `tests/test_s5.py`

## The recurrence

Same discrete-time equation as S4D's:

$$x_t = \bar{A} x_{t-1} + \bar{B} u_t, \qquad y_t = \mathrm{Re}(C x_t) + D u_t$$

Same equation, different shapes. In S4D, $x_t \in \mathbb{C}^N$ is one
independent state *per channel* — $d_{model}$ of them, never interacting
until the surrounding FFN mixes channels back together. In S5, $x_t \in
\mathbb{C}^P$ is a **single state shared across every channel**. $\bar B
\in \mathbb{R}^{P \times d_{model}}$ and $C \in \mathbb{R}^{d_{model}
\times P}$ are now genuine matrices: every channel's input gets routed
into the shared state via $\bar B$, and every channel's output reads a
learned combination of the whole state back out via $C$. Cross-channel
mixing happens *inside* the recurrence now, not only around it.

$A$ is still diagonal. $\bar A = e^{\Delta A}$ is still a learned
constant, not a function of the input — S5 and S4D sit in the exact same
place on the selectivity axis (see `docs/00_research_lineage.md`). The
only axis that moved is MIMO vs. SISO.

## Why this reuses S4D's scan unchanged

The whole reason S5 was the cheap next step after S4D: once $\bar B u_t$
is computed for every timestep — one batched matrix-vector product,
`torch.einsum("ph,blh->blp", B_bar, x)`, done once before the recurrence
runs — what's left is exactly the same elementwise affine recurrence
`ssm_lab.utils.scan.parallel_scan_log` already implements and already has
correctness tests for. S5 needed zero new scan code. Mamba (model 3) is
the first model in this repo that will actually require extending
`ssm_lab.utils.scan` to take an input-dependent `a_t` — S5 doesn't touch
that boundary at all.

## Parameterization choices, and why

- **$A$**: same `-exp(log_A_real) + i * A_imag` reparameterization as
  S4D, same guarantee that $\mathrm{Re}(A) < 0$ for any real parameter
  value. Initialized from `ssm_lab.utils.hippo.hippo_diag_spectrum` —
  the same function S4D uses, *unrepeated* across channels here, since
  there's only one shared spectrum, not one per channel. This is a
  deliberate reuse, not a coincidence: extracting that spectrum
  computation out of `s4d.py` and into `ssm_lab.utils.hippo` was the
  first step in building this model — S4D's tests were re-run
  immediately after that refactor specifically to confirm it changed
  nothing about S4D's behavior before S5 ever used the extracted
  function.
- **$B$, $C$ — both learned, both randomly initialized.** This is the
  one place S5's parameterization genuinely can't copy S4D's shortcut.
  S4D fixes $B$ at all-ones because, with a *diagonal* per-channel A,
  $B$'s scale is redundant with $C$'s — rescale one, rescale the other
  inversely, nothing changes. That argument depends on $B$ and $C$ being
  scalars. Here they're a $(P, H)$ and $(H, P)$ matrix respectively, and
  a fixed $B$ (e.g. all-ones) would force every one of the $P$ states to
  read an identical fixed combination of input channels — deleting
  exactly the cross-channel routing capacity that's the point of this
  model. Both are initialized $\mathcal{N}(0, 1/\text{fan-in})$, standard
  practice for a learned linear map.
- **$\Delta$ (step size)**: per-state-dimension (shape `(P,)`), not
  per-channel — there's no channel axis left in the state to attach a
  per-channel Δ to. Same log-uniform-then-learned scheme as S4D.
- **$D$ (skip term)**: per-channel, shape `(d_model,)`, identical role
  and identical shape to S4D's — the one parameter S5 keeps exactly
  S4D's shape for, since the skip connection operates in channel space
  (`D * u_t`) regardless of what the recurrent core looks like.

## What's simplified relative to the original S5 paper, and why that's defensible

Smith, Warrington & Linderman derive their diagonal $A$ from an
eigendecomposition of a normal approximation to the HiPPO-LegS matrix —
a specific, separate derivation from S4D-Lin/S4D-Inv, though both are
diagonal approximations to the same underlying spectrum. This repo
reuses S4D's exact `hippo_diag_spectrum` for both models rather than
re-deriving S5's own eigendecomposition. Trade-off, stated plainly:
slightly less faithful to the original paper's specific initialization
scheme, in exchange for one shared, already-tested reference
implementation of "diagonal HiPPO approximation" serving every model in
this repo that needs one, rather than a second subtly-different
derivation to maintain and re-verify independently.

Same full-complex-state simplification as S4D (no conjugate-pair
halving) — see `docs/01_s4.md` for the reasoning, unchanged here.

## Correctness evidence (see `tests/test_s5.py`)

- **`forward()` exactly matches `step()`-by-`step()`**, the same
  independent-code-path verification pattern as S4D's, to `atol=1e-4`.
- **Causality**, checked directly.
- **Gradients finite** through every parameter (including the now-larger
  set of complex ones — $B$ and $C$ are full matrices here, not
  per-channel scalars), AdamW steps without error.
- **The state really is shared, not per-channel** — `init_state(batch)`
  returns shape `(batch, d_state)`, no `d_model` dimension at all,
  checked directly (`test_state_is_shared_across_channels_not_per_channel`).
  If this ever regressed to a per-channel shape, S5 would quietly become
  a second copy of S4D instead of the MIMO model it's supposed to be.
- **$B$ and $C$ actually mix channels** — perturbing a single input
  channel measurably affects *multiple* output channels
  (`test_B_and_C_actually_mix_channels`), the direct structural
  consequence of routing through a shared state that S4D's per-channel
  isolation can't produce. This is the one test in this repo so far
  that verifies an architecture is doing what it's *supposed* to
  architecturally, not just that its math is internally consistent.

## Results (`notebooks/02_s5.ipynb`) and what they mean

Predictions were written into the notebook *before* it was run (same
discipline as `01_s4.ipynb`): MIMO mixing is orthogonal to selectivity,
so S5 should fail the same benchmarks S4D fails, for the same reason,
and only clearly separate from S4D on throughput. The dev-run sweep
matched that prediction closely:

| benchmark | val_acc | val_loss | note |
|---|---|---|---|
| MQAR | 0.025 | 3.435 | near chance (~0.03) — same as S4D's 0.021 |
| Copying (len 8, d_state 64) | 0.959 | 0.548 | holds up, as expected at this state size |
| Induction heads | 0.062 | 2.710 | at chance (1/16 = 0.0625) |
| Parity | 0.627 | 0.550 | above chance (0.5), weak |
| S5 (group) tracking | 0.111 | 4.700 | above chance (1/120 ≈ 0.008), still weak |
| Real LM (tiny-shakespeare) | — | 2.377 | perplexity 256 → **10.8** |

MQAR and induction landing at chance, right alongside S4D's own numbers,
is the headline result here — not a disappointing one. It's direct
evidence that *selectivity*, not *MIMO-ness*, is the axis that actually
governs recall, exactly what motivated writing the prediction down before
running anything. Real language modeling works, same as S4D. Model 3
(Mamba) is where this repo's roadmap finally changes the axis that
matters.
