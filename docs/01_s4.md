# Model 1/14: S4D

Code: `src/ssm_lab/layers/s4d.py` · Notebook: `notebooks/01_s4.ipynb` · Tests: `tests/test_s4d.py`

## The recurrence

For each channel independently, a diagonal, complex, continuous-time
linear state-space model:

$$\dot{x}(t) = A x(t) + B u(t), \qquad y(t) = \mathrm{Re}(C x(t)) + D u(t)$$

with $A \in \mathbb{C}^N$ diagonal (per channel), discretized via
zero-order hold at a learned per-channel step size $\Delta$:

$$\bar{A} = e^{\Delta A}, \qquad \bar{B} = A^{-1}(\bar{A} - I) B$$

giving the discrete recurrence actually run by the code:

$$x_t = \bar{A} x_{t-1} + \bar{B} u_t, \qquad y_t = \mathrm{Re}(C x_t) + D u_t$$

## Parameterization choices, and why

- **$A = -e^{\text{log\_A\_real}} + i \cdot A_{\text{imag}}$.** The
  $-\exp(\cdot)$ reparameterization guarantees $\mathrm{Re}(A) < 0$ (a
  stable, decaying mode) for *any* real value of the underlying parameter,
  so gradient descent can never push the system into an exploding
  regime. Standard S4/S4D trick.
- **$A_{\text{imag}}$ initialized from a diagonal approximation to the
  HiPPO-LegS spectrum** (S4D-Lin: $\pi n$ for state index $n$; S4D-Inv:
  closer to the true asymptotic falloff). This is what lets a S4D layer
  start training already "shaped like" a good online function
  approximator, rather than from a random guess.
- **$B$ initialized to all-ones.** With diagonal $A$, $B$'s magnitude is
  redundant with $C$'s (rescaling $B$ by $k$ and $C$ by $1/k$ leaves $y$
  unchanged), so there's nothing to gain from a fancier init here — this
  matches the original S4D paper's choice.
- **$C$ is the only randomly-initialized SSM parameter.**
- **Step size $\Delta$** is drawn log-uniformly from `[dt_min, dt_max]` at
  init and then learned per channel. This is the one S4/S4D hyperparameter
  that matters most in practice: it controls what timescale of memory
  each channel specializes in.
- **$D$** (feedthrough / skip term) lets the layer pass the raw input
  through directly, which in practice makes early training much easier
  (the layer doesn't have to learn the identity function through the SSM
  before it can learn anything else).

## What's simplified relative to "full" S4, and why that's a defensible choice here

Full S4 (Gu, Goel & Ré, 2022) parameterizes $A$ as Normal-Plus-Low-Rank
(NPLR): $A = \Lambda - PQ^*$ for diagonal $\Lambda$ and low-rank $P, Q$.
Because $A$ isn't diagonal, computing the convolution kernel requires a
specific trick — evaluating a Cauchy kernel at the roots of unity via the
Woodbury identity — to stay subquadratic. That machinery is intricate
enough that most from-scratch "build S4" implementations (this one
included) implement S4D instead, trading some representational capacity
(a diagonal $A$ is less expressive than NPLR) for an implementation whose
correctness can actually be checked end to end, which is exactly what
`tests/test_s4d.py` does.

Two further simplifications, both deliberate and both noted as first
optimization targets rather than hidden:

1. **Full complex state, no conjugate-pair halving.** HiPPO-derived
   spectra come in complex-conjugate pairs; a tuned implementation tracks
   only half the state and doubles the real part of the output projection
   to recover the full sum. This repo tracks the full $N$-dimensional
   complex state directly — roughly 2x the compute/memory of a tuned
   implementation at the same $N$, in exchange for a forward pass with no
   "why is there a factor of 2 here" step to explain.
2. **Evaluated via the parallel scan, not the FFT-convolution path.**
   Because $\bar A, \bar B$ don't depend on time for S4D, the "textbook"
   fast path is to compute the length-$L$ convolution kernel directly
   (closed-form geometric series, since $\bar A$ is diagonal) and convolve
   via FFT. This repo instead reuses
   `ssm_lab.utils.scan.parallel_scan_log` — the same $O(\log L)$
   associative-scan primitive S5, Mamba's selective scan, and (with a
   data-dependent $a_t$) the GLA/DeltaNet/RWKV-7 family in this repo all
   reduce to. The unifying view this buys — "every model in this repo is
   the same scan with a different $(a_t, b_t)$" — was worth more for this
   project than the extra constant-factor speed of the FFT path.

## Correctness evidence (see `tests/test_s4d.py`)

- **`forward()` (scan-based) exactly matches `step()`-by-`step()`**, a
  completely independent code path implementing the recurrence one token
  at a time. Verified to `atol=1e-4`.
- **Causality**: perturbing the input at position $t \geq 7$ provably
  doesn't change the output at positions $< 7$.
- **Gradients are finite through every complex parameter**, and AdamW can
  step them without error — complex-valued autograd is well-supported in
  modern PyTorch, but worth checking explicitly rather than assuming.

## Results (`notebooks/01_s4.ipynb`) and what they mean

S4D's transition is a *learned constant* — no mechanism to decide what to
write into or read out of the state based on content. Expected, and
observed in the FAST_DEV_RUN sweep already in the notebook:

- **Copying** holds up until `copy_len` approaches `d_state`, then falls
  off — a genuine capacity limit.
- **MQAR and induction heads** are weak. Both need "notice this specific
  token, remember it, retrieve it on demand" — content-based routing a
  fixed-decay recurrence has no mechanism for.
- **Parity and S5 state-tracking** are weak-to-failing, especially S5 —
  the Merrill et al. (2024) result, reproduced rather than asserted.

This is the point of building S4D first: it gives the next 13 models in
`ROADMAP.md` something concrete to beat, on benchmarks chosen specifically
because they separate architectures for structural reasons, not by luck
of hyperparameters.
